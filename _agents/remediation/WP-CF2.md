# Work Package Report: WP-CF2 — Corpus Audit, Glyph Remediation & Generator Hardening

## Executive Summary

Work Package **WP-CF2** addresses and remediates the two critical issues discovered during the first live honest evaluation run on deck `d03`:
1. **Missing Vulgar Fraction Glyphs in Handwriting Fonts**:
   The vintage cursive handwriting font (`marck_script.ttf`) completely lacked glyphs for vulgar fraction Unicode code points (`½`, `⅓`, `¼`, `¾`, etc.). Because FreeType returns an empty mask for unmapped glyphs, Pillow silently rendered empty spaces without raising an error (e.g., rendering `"cup butter"` instead of `"½ cup butter"`), while ground truth required `"1/2"` or `"½"`. This resulted in an unfair evaluation benchmark that corrupted ingredient extraction and quantity accuracy metrics.
2. **Title/Body Mismatch in Synthetic Near-Duplicate Pairs**:
   In deck `d03`, near-duplicate pairs were generated by simply overwriting the title of recipe index 1 with `f"{rec0['title'][:-2]} II"` without altering or pairing the recipe body. This resulted in recipe 25 (Hot Cross Buns) carrying the title `"Dutch Apple Cake II"`. In addition, Project Gutenberg nutritional tables and illustration captions were occasionally swallowed into preceding recipe directions due to lax header detection.

WP-CF2 comprehensively resolves these issues by:
- Conducting an exhaustive character map (cmap) audit across all bundled fonts and characters present in historical recipe corpora.
- Hardening `cardforge` with mandatory glyph validation (`validate_font_glyphs`), automated self-checks (`MissingGlyphError`), consistent fraction transliteration (`adapt_text_for_font`), and per-character fallback font rendering (`draw_text_with_fallback`).
- Implementing semantic title/body consistency validation (`check_title_body_consistency`) and authentic near-duplicate variation generation (`make_near_duplicate_variant`).
- Regenerating both Tier 1 (dev-eval) and Tier 2 (held-out) corpora and re-encrypting all ground truth vault artifacts.
- Spot-verifying regenerated card images via direct visual inspection (`view_file`), confirming clear, verbatim fraction visibility across all font styles.

## Font Glyph Audit

We evaluated font cmap coverage using `fonttools` across all bundled fonts in `cardforge/fonts/` (`caveat.ttf`, `special_elite.ttf`, `marck_script.ttf`) and system fallback fonts (`DejaVuSans.ttf`, `DejaVuSerif.ttf`) against all characters present in historical recipe corpora (letters, digits, punctuation, typographic symbols, and fraction codepoints).

### Root Cause Analysis: Silent Blank Rendering
In FreeType/Pillow, when a character code point is missing from a TrueType `cmap` table, FreeType returns glyph index 0 (`.notdef`). In `marck_script.ttf`, glyph 0 has a zero-width empty bounding box. Consequently:
- `draw.text()` printed nothing on the canvas for `½`, leaving a whitespace hole.
- No exception or warning was raised by Python or Pillow.
- Ground truth recorded the unrendered fraction, making OCR extraction impossible and penalizing honest models.

## CardForge Engine Hardening

To prevent silent glyph drops and guarantee verbatim consistency between card images and evaluation ground truth, `cardforge` was hardened in `cardforge/generator.py` and exported through `cardforge/__init__.py`:

### 1. Fast Cmap Caching & Inspection
- `get_font_cmap(font_or_path)`: Uses `fontTools.ttLib.TTFont` to extract and cache the set of supported character code points (`_CMAP_CACHE`).
- `check_font_missing_glyphs(text, font_or_path)`: Returns a set of missing characters with code points for any input text string.

### 2. Self-Check & `MissingGlyphError`
- Added `MissingGlyphError(ValueError)` exception class.
- Added `validate_font_glyphs(text, font, font_style)`: Validates that every character in `text` has a valid glyph in `font`. If any missing glyphs are detected, generation **immediately fails with a descriptive error** identifying the character and Unicode codepoint (e.g. `Character '½' (U+00BD) lacks glyph in font 'marck_script'`).
- Integrated validation into:
  - `render_handwritten_lines`: Validates each line before baseline wobbling and rasterization.
  - `render_typewritten_lines`: Validates each line before character bounce and ribbon wear simulation.
  - `generate_recipe_card_faces`: Validates recipe titles, headers, ingredient lines, direction lines, metadata footers, and continuation cues (`over`, `pto`, etc.).

### 3. Font-Aware Text Adaptation (`adapt_text_for_font`)
- Before rendering and before constructing ground truth records, recipe text is passed through `adapt_text_for_font(text, font_style)`.
- If a font lacks vulgar fraction glyphs (such as `marck_script` or `special_elite`), vulgar fractions are transliterated to ASCII fraction representations:
  - `½` $\rightarrow$ `"1/2"`
  - `⅓` $\rightarrow$ `"1/3"`
  - `⅔` $\rightarrow$ `"2/3"`
  - `¼` $\rightarrow$ `"1/4"`
  - `¾` $\rightarrow$ `"3/4"`
  - `⅛` $\rightarrow$ `"1/8"`, etc.
- Also standardizes typographic dashes and smart quotes to ASCII equivalents when unsupported.
- Crucially, `build_synthetic.py` adapts both the visual canvas text **and** the structured ground truth (`parse_ingredient_line(adapted_ing)`). Ground truth quantities (`quantity: "1/2"`), raw strings (`"1/2 cup butter"`), and image pixels are 100% synchronized.

### 4. Per-Character Fallback Font Rendering (`draw_text_with_fallback`)
- Added per-character fallback font drawing. If a character is absent from the primary font, it is rendered seamlessly using an available fallback font (e.g. DejaVu or Caveat) at equivalent line height, ensuring graceful degradation.

## Title/Body Consistency & Generator Fixes

### 1. Near-Duplicate Pair Generation (`make_near_duplicate_variant`)
- Previously, `build_synthetic.py` overrode `d03_recipes[1]["title"] = f"{d03_recipes[0]['title'][:-2]} II"` without changing the body, leaving Recipe 25 ("Buns") labeled as "Dutch Apple Cake II".
- Replaced with `make_near_duplicate_variant(base_recipe, variant_title, variant_type, seed)`:
  - Clones the base recipe data.
  - Generates realistic, authentic culinary variations of the same dish:
    - Adjusts ingredient quantities (e.g. `1/3 cup sugar` $\rightarrow$ `1/2 cup sugar`, `3 cups flour` $\rightarrow$ `3 1/4 cups flour`).
    - Adjusts baking times and oven temperatures (e.g. `30 minutes` $\rightarrow$ `35 minutes`).
    - Adds subtle ingredient additions (e.g. `1/2 tsp vanilla extract` or `1/4 tsp ground cinnamon`).
  - Maintains semantic integrity so titles and bodies are genuinely aligned.

### 2. Semantic Title/Body Consistency Checker (`check_title_body_consistency`)
- Implemented `check_title_body_consistency(title, ingredients, directions)`:
  - Scans for 50+ distinctive culinary keywords in recipe titles (e.g., `apple`, `oatmeal`, `banana`, `squash`, `chocolate`, `ginger`, `claret`, `bread`, `soup`).
  - Verifies that when a distinctive ingredient is named in the title, it appears in either the ingredients list or the directions text.
  - Verifies that key substantive title words exist in the body.
  - Integrated into `build_synthetic.py` generation loop to assert consistency on every generated recipe.

### 3. Historical Text Parsing Cleanup (`parse_recipes_from_text`)
- Fixed Gutenberg ingestion regexes:
  - Ignored illustration captions (e.g. `[Illustration: ...]`).
  - Filtered out non-recipe introductory nutritional tables (e.g. Fannie Farmer dietary averages).
  - Ensured multi-line direction collection stops cleanly when the subsequent uppercase recipe title is encountered.

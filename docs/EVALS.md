# RecipeBoxer Evaluation Framework (EVALS)

This document specifies the honest benchmarking methodology, corpus tier taxonomy, cryptographic ground-truth vault, black-box execution harness, scoring protocols, cost guidance, and baseline comparisons for **RecipeBoxer**.

---

## 1. Honesty Rules & Remediation Context

### 1.1 The October 2026 Audit Findings
Prior to the remediation initiative, an internal audit ([`_agents/remediation/REMEDIATION_PLAN.md`](../../../../../../storage/emulated/10/AntiGravity/Workspaces/recipeboxer/_agents/remediation/REMEDIATION_PLAN.md) §2) uncovered severe evaluation cheats and answer-key leaks:
- **Direct Manifest Lookups**: `extractor.py:125-193`, `semantic.py:48-71`, and `router.py:35-58` checked image SHA-256 hashes against `manifest.json`, returning pre-computed recipe text and cluster assignments without executing models.
- **Filename Semantics**: `fingerprint.py:253-379` and `heuristics.py:512-567` inspected card filenames for tokens (`front`, `back`, `card1`, category codes), synthesizing card roles, rulings, ink colors, and continuation links from filename strings.
- **Canned Recipe Fallbacks**: `extractor.py:773-901` hardcoded full recipe outputs (cinnamon rolls, lemon bars, fudge, pecan pie) on missing keys or failures.
- **Harness Leaks**: The legacy harness preserved original image SHA-256 hashes across obfuscation, passed ground-truth attributes directly to the System Under Test (SUT), maintained a global de-obfuscation registry, and defaulted to an offline mock judge returning 4.96 / 5.0.

### 1.2 The Non-Negotiable Honesty Invariants
To guarantee all reported scores reflect genuine machine intelligence from pixels to predictions, six non-negotiable invariants are enforced across the codebase ([`_agents/INVARIANTS.md`](../../../../../../storage/emulated/10/AntiGravity/Workspaces/recipeboxer/_agents/INVARIANTS.md) §10):
1. **INV-AC1 (No Answer Key)**: Production code under `recipeboxer/` cannot read evaluation directories (`evals/`, `tests/`), manifests, vault files, or age decryption keys.
2. **INV-AC2 (No Filename Meaning)**: Filenames and card IDs are strictly opaque identifiers (`secrets.token_hex(6)`). No token, keyword, or regex heuristics are permitted.
3. **INV-AC3 (No Corpus Content)**: No ground-truth titles, distinctive phrases, or fixture hashes exist as literals in production code.
4. **INV-AC4 (No Silent Fabrication)**: Pipeline failures produce explicit `StageFailure` records; silent fallbacks to stubs or canned text are strictly prohibited.
5. **INV-AC5 (Black-Box Evals)**: The SUT runs in an isolated subprocess with an active `sys.addaudithook` preventing file access to evaluation ground truth or fixtures.
6. **INV-AC6 (LLM Required)**: Multimodal LLM execution is mandatory; without an API key, the system remains in a blocked onboarding state. OCR provides boundary cues and grounding verification only, never an extractor fallback.

## 2. Corpus Tier Architecture (T0–T4)

The evaluation corpora are divided into five distinct tiers balancing developer velocity, procedural secrecy, and real-world validation:

| Tier | Name | Contents | Images Public? | Ground Truth Public? | Purpose | Feedback Allowed |
|:---:|---|---|:---:|:---:|---|:---:|
| **T0** | **Train** | 48 synthetic cards (24 recipes) across 6 modalities | **Yes** | **Yes** (plaintext in `tests/fixtures/`) | Unit tests, feature weight fitting, calibration, prompt engineering | Aggregate & Per-Item |
| **T1** | **Dev-Eval** | Synthetic multi-card decks generated by CardForge from external recipes | **Yes** (`evals/corpora/t1/`) | **No** (encrypted in `evals/vault/t1.gt.enc`) | Routine honest measurement and regression testing | Aggregate only |
| **T2** | **Held-Out** | Synthetic decks with separate recipes, seeds, 3–5 face chains, and distractors | **No** (encrypted in `evals/vault/t2.images.tar.enc`) | **No** (encrypted in `evals/vault/t2.gt.enc`) | Gate A and Gate B certification; prevents tuning on T1 | Aggregate only (Gates only) |
| **T3** | **Real-Web** | Public-domain photos of real historical recipe cards with human transcriptions | **Yes** (`evals/corpora/t3/`) | **No** (encrypted in `evals/vault/t3.gt.enc`) | Real-world handwriting extraction and distractor grouping | Aggregate only |
| **T4** | **Real-User** | Genuine family recipe collections photographed on smartphone cameras | Per user preference | **No** (encrypted in vault) | Ultimate real-world performance milestone | Aggregate only |

## 3. Black-Box Harness & Audit Hook

The evaluation harness ([`evals/harness/run.py`](../../../../../../storage/emulated/10/AntiGravity/Workspaces/recipeboxer/evals/harness/run.py)) executes the production CLI entry point (`recipeboxer analyze --input DIR --out FILE --auto-approve`) in strict isolation:

```
                  ┌──────────────────────────────────────────────┐
                  │           evals.harness.run                  │
                  │   - Randomizes image filenames and ordering  │
                  │   - Scrubs environment (scrubs keys/secrets) │
                  │   - Sets CWD to isolated temporary directory │
                  └──────────────────────┬───────────────────────┘
                                         │
                                         ▼ Subprocess
                  ┌──────────────────────────────────────────────┐
                  │             SUT Subprocess                   │
                  │   - Injects sys.addaudithook (sut_boot.py)   │
                  │   - Executes production headless pipeline    │
                  └──────────────────────┬───────────────────────┘
                                         │ Attempt to read evals/ or *.gt.enc?
                                         ├──► [CHEAT_DETECTED: Exit 86]
                                         │
                                         ▼ Clean Exit
                  ┌──────────────────────────────────────────────┐
                  │   Outputs Artifacts (DIR/):                  │
                  │   - outputs.json (rb-out/1 predictions)      │
                  │   - ledger.json (token usage & USD spend)    │
                  │   - run.log (complete subprocess stdout)     │
                  └──────────────────────────────────────────────┘
```

### 3.1 Subprocess Environment Sanitization
- **Scrubbed Environment**: All environment variables containing `AGE`, `VAULT`, `SECRET`, or `RB_EVAL` are stripped. Only an explicit allowlist (`PATH`, `PYTHONPATH`, locale, and injected live Gemini keys) is passed. `HOME`/`TMPDIR`/`XDG_*` are replaced by a private per-deck sandbox (§3.2).
- **Randomized Opaque Filenames**: Deck images are copied to an ephemeral directory with random 12-hex filenames (`secrets.token_hex(6)` + extension) and shuffled order. The harness maps opaque names back to original corpus IDs **after** the SUT process terminates.
- **Naming Variants (`--variant`)**:
  - `opaque`: Default randomized names.
  - `misleading`: Adversarial naming swapping "front" and "back" labels and altering card numbers.
  - `shuffle`: Randomizes directory traversal order.
  - `reencode`: Re-compresses images across JPEG, PNG, and WebP formats.

### 3.2 Runtime Anti-Cheat Audit Hook (`evals/harness/sut_boot.py`)
At process initialization, `sut_boot.py` installs a Python runtime audit hook (`sys.addaudithook`):
- Intercepts file open events (`open`, `io.open`, `os.open`).
- **SUT sandbox (RT3-01, WP-RT3FIX)**: each deck's SUT subprocess gets a fresh private `HOME`, `TMPDIR`/`TEMP`/`TMP` and `XDG_{CONFIG,CACHE,DATA,STATE,RUNTIME}` tree (`evals/harness/run.py::prepare_sut_sandbox`). `PROJECT_CACHE_DIR` is not forwarded. The hook config is passed in `RB_SUT_SANDBOX` and removed from the SUT's environment at boot.
- **Strict allowlist (harness mode)**: every opened, listed or globbed path must lie in the interpreter prefixes (venv, stdlib, site-packages), the pycache prefix, the `recipeboxer` package dir, the cwd/input dir, the private sandbox, or a system dir (`/dev`, `/proc` for the SUT's own process only, `/sys`, `/etc`, `/usr/share`, `/usr/lib*`, `/lib*`). The import machinery may list (not open) the exact `sys.path` entries.
- **Deny roots and name patterns (always on)**: `$HOME/.cache/projects/**` of the current HOME, plus the harness-passed real `$HOME/.cache/projects`, `~/.config/recipeboxer`, `~/.gemini` and the Antigravity artifact dir (`*/AntiGravity/.gemini`). Interpreter-owned roots are exempt. Path segments `/.gemini/`, `/t3gt/`, `/t3_cache/`, `/gutenberg_cache/`, `/t2_corpus_`, `/honest_v*`, `/bench_out`, `/redteam*` and `/cardforge/` are denied anywhere.
- If any read attempts target `evals/`, `tests/fixtures/`, `manifest.json`, `*.gt.enc`, or age key paths (or any of the paths above), the audit hook:
  1. Immediately emits `CHEAT_DETECTED: Unauthorized access to <path>` to `stderr`.
  2. Terminates the SUT subprocess with exit code **86**.
  3. Sets SUT run status to `"cheat_detected"` in `outputs.json`.

## 4. Ground-Truth Vault & Key Architecture

### 4.1 Cryptographic Storage (`evals/vault.py`)
- Ground truth for tiers T1–T4 is stored strictly encrypted with **`age`** (via `pyrage`).
- The vault uses multi-recipient encryption keyed to maintainer and CI public keys listed in [`evals/vault/recipients.txt`](../../../../../../storage/emulated/10/AntiGravity/Workspaces/recipeboxer/evals/vault/recipients.txt).
- Private age identity keys are stored outside the repository workspace (default: `~/.config/recipeboxer/age.key` or `RB_EVAL_AGE_KEY_FILE`).
- `evals/vault.py` enforces stack-frame inspection refusing to run if imported by `recipeboxer.*`.

### 4.2 Multi-Machine & Contributor Workflow
For full details on CI secrets, maintainer setup, and contributor workflows, refer to [**`docs/CI.md`**](CI.md):
- **Local Contributors**: Can run the full offline suite on T0 with per-item diffs. Can execute the production pipeline against public T1 images using their own API key, but **cannot score T1–T4** without an age identity key.
- **CI Two-Workflow Split**:
  1. `eval-run.yml`: Runs untrusted pull request code with `CI_GEMINI_API_KEY` (maintainer-approved in `eval-live` environment) and **zero vault secrets**, uploading `sut-outputs`.
  2. `eval-score.yml`: Triggers on `workflow_run`, checks out **trusted `main` branch only**, mounts `CI_AGE_IDENTITY`, decrypts `t1.gt.enc`, scores the artifact, and posts an aggregate comment.

## 5. Scoring Protocols & Metric Taxonomy

Scoring is executed by the standalone scorer CLI ([`evals/score.py`](../../../../../../storage/emulated/10/AntiGravity/Workspaces/recipeboxer/evals/score.py)):

```bash
python -m evals.score \
  --tier T1 \
  --outputs path/to/run_dir \
  --report path/to/report_dir \
  --feedback aggregate \
  --compare evals/baselines/honest_v0.json
```

### 5.1 Grouping Metrics (`evals/metrics/grouping.py`)
- **B-Cubed Precision, Recall & F1**: Element-level clustering metrics evaluating whether cards belonging to the same recipe are grouped together.
- **Adjusted Rand Index (ARI)**: Chance-adjusted cluster similarity.
- **Exact Cluster Accuracy**: Proportion of predicted recipe groups that match ground-truth card sets perfectly.
- **Order Kendall's $\tau$**: Measures reading order correctness across multi-face recipe sequences.
- **Standalone Accuracy**: Grouping precision on single-sided standalone cards.
- **False-Merge Rate & False-Split Rate**: Error diagnostics tracking improper merging of distinct recipes versus improper splitting of multi-card sets.

### 5.2 Extraction Metrics (`evals/metrics/extraction.py`)
Predictions are Hungarian-matched to ground-truth recipes based on card-overlap Intersection over Union (IoU) and content similarity:
- **Title CER**: Character Error Rate between predicted and gold titles.
- **Ingredient Precision, Recall & F1**: Line-level Hungarian matching requiring Character Error Rate $\le 0.10$.
- **Quantity & Unit Exact Match**: Precision on parsed numerical quantities and units.
- **Direction F1 & Order $\tau$**: Instruction step match rate and sequence ordering.
- **Hallucination & Omission Rates**: Measures unsupported recipe content vs unextracted gold content.
- **Illegible Precision**: Accuracy of `[illegible: reason]` markers when transcribing damaged text.
- **Confidence Calibration (ECE)**: Expected Calibration Error across 10 bins comparing the SUT's `recipes[].confidence` to correctness (matched recipe with content similarity >= 0.5 AND ingredient F1 >= 0.7). See §5.5.

#### Matched-Only vs. End-to-End Metric Populations
The scorer reports extraction metrics under two distinct scopes:
- **Matched-Only (`extraction_matched_only`)**: Evaluates extraction quality strictly on predicted recipes that successfully match a ground-truth recipe. Unmatched predictions (grouping split fragments or hallucinations) and omitted gold recipes are excluded from per-field means. This isolates transcription/structuring fidelity from grouping errors.
- **End-to-End (`extraction_end_to_end`)**: Evaluates entire pipeline performance from pixels to recipes. Omitted gold recipes are scored with zero precision/recall and 1.0 omission rate; unmatched predicted recipes count as hallucinations. This captures the complete user-facing accuracy including grouping splits and merges.


### 5.3 Operational & LLM Judge Metrics
- **Operational Metrics (`evals/metrics/ops.py`)**: Total HTTP calls, token consumption (input, output, reasoning), latency percentiles, stage-level failures, and total USD spend calculated from `recipeboxer/data/pricing.toml`.
- **LLM-as-a-Judge (`evals/judge.py`)**: Blinded rubric evaluation (0–5 scale) assessing culinary coherence and formatting. **Must use a different model tier than the extractor** (e.g. Pro judge if extractor is Flash) to prevent self-preference bias. Judge scores are informational and never gate.

### 5.4 Feedback Policy
- **Tier T0**: Allows `--feedback aggregate` or `--feedback per_item` for granular line-by-line debugging.
- **Tiers T1–T4**: Strictly **aggregate only**. Passing `--feedback per_item` raises `ValueError`, and all per-item diffs are stripped from reports to prevent test-set memorization.

### 5.5 Calibration Populations (RT3-02, WP-RT3FIX)
The scorer (`evals/scoring/evaluator.py::calibration_summary`) reports `metrics.calibration` with:
- **`ece_all`** (headline; also exposed as `ece`): ECE over **every predicted recipe that carries a confidence**. Unmatched predictions (hallucinated recipes, grouping fragments) are scored as **incorrect**.
- **`ece_matched`** (diagnostic): the same ECE restricted to Hungarian-matched predictions. Before WP-RT3FIX this was the only ECE reported (under `ece`). It excludes false-positive recipes, so it flatters calibration. Do not quote it as the headline number.
- **`confidence_coverage`** = `n_with_confidence / n_pred`. A `None` confidence is an abstention. It is not scored in ECE, but it lowers coverage. Always report coverage next to ECE, because a SUT could otherwise improve ECE by withholding doubtful confidences.
- Counts: `n_pred`, `n_with_confidence`, `n_matched_with_confidence`, `accuracy_all`, `mean_confidence_all`.

> [!NOTE]
> The UP3 `recipe` confidence model (`calibration_default.json["up3"]["models"]["recipe"]`) was fitted on fresh decks, but only on **matched** predicted recipes (it never saw a false-positive recipe). Its held-out "ECE ≈ 0.05" claim (WP-UP3) is therefore a matched-only number. Use `ece_all` for Gate claims. See `_agents/remediation/WP-RT3FIX.md` for the refit status and the before/after held-out numbers.

> [!WARNING]
> Baselines recorded before WP-RT3FIX store the matched-only value under `calibration.ece`. When comparing against such a baseline, compare against `ece_matched`.

## 6. How to Run Evaluations & Cost Guidance

### 6.1 Execution Commands

```bash
# 1. Run SUT on Tier 1 with a $5.00 budget cap using Balanced profile
python -m evals.harness.run \
  --tier T1 \
  --out evals/reports/run_t1_balanced \
  --profile balanced \
  --budget-usd 5.00 \
  --timeout 600

# 2. Score predictions against encrypted ground truth and compare against honest baseline
python -m evals.score \
  --tier T1 \
  --outputs evals/reports/run_t1_balanced \
  --report evals/reports/report_t1_balanced \
  --compare evals/baselines/honest_v0.json

# 3. Generate Oracle Grouping Plan (evaluates extraction isolated from grouping)
python -m evals.score oracle-plan --tier T1 --out /tmp/t1_oracle_plan.json

  --tier T1 \
  --out evals/reports/run_t1_oracle \
  --oracle-plan /tmp/t1_oracle_plan.json \
  --budget-usd 5.00
```

## 8. Real-World Corpora Curation (T3 & T4)

### 8.1 Tier T3 (Real-Web) Curation Pipeline
- **Sources**: Public-domain archival recipe collections:
  - *Smithsonian Transcription Center*: CC0 volunteer-transcribed historic cards and recipe scrapbooks.

  - *Wikimedia Commons*: CC0 / CC-BY / CC-BY-SA recipe cards.
  - Complete license logs maintained in `evals/corpora/real_web/ATTRIBUTION.md`.
- **Memorization Probe**: Prior to inclusion, candidates undergo a memorization probe: the model is prompted with the recipe title alone. Any recipe completed verbatim from model memory is discarded to ensure models have not memorized the text during training.
- **Ground Truth Construction**:
  - Verbatim text is derived directly from human volunteer transcriptions (trusted).
  - Structured ground truth is drafted text-only (never from the card image) using an independent model tier.
  - Maintainers spot-check ~20% of structured ground truth via [`evals/curation_t3/spotcheck.py`](../../../../../../storage/emulated/10/AntiGravity/Workspaces/recipeboxer/evals/curation_t3/spotcheck.py).

### 8.2 Tier T4 (Real-User) Photo Intake Plan
Tier 4 incorporates personal recipe collections. Follow the intake guide in [**`evals/INTAKE.md`**](../../../../../../storage/emulated/10/AntiGravity/Workspaces/recipeboxer/evals/INTAKE.md):
- **Photo Recommendations**: 10–20 recipes, at least 5 multi-card sets. Shoot in natural kitchen lighting in sequential camera-roll order.
- **Privacy Stripping**: The intake tool ([`evals/intake_real.py`](../../../../../../storage/emulated/10/AntiGravity/Workspaces/recipeboxer/evals/intake_real.py)) permanently strips GPS coordinates and device serial numbers while preserving `DateTimeOriginal` for capture sequence evaluation. Images are assigned opaque random 12-hex IDs.
- **Paid API Key Recommendation**: For personal or family recipe cards, **use a paid Gemini API key with a spend cap** in Google AI Studio. Google's terms for free-tier API usage permit user inputs to be used for model training; paid tier usage generally does not.
